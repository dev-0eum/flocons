# flocons — 하네스 운영 매뉴얼

> 컴퓨터가 켜져 있는 동안 자율적으로 개발을 이어가며, 검증을 통과한 변경만 `main`에 푸시한다.
> 이 문서는 자율 루프가 매 반복마다 따르는 절차·게이트·안전수칙을 규정한다.

---

## 1. 실행 모델

- **메커니즘**: 자기 페이싱(self-paced) `/loop`. 매 깨어남마다 "다음 한 단위 작업"을 수행하고 다음 깨어남을 예약한다.
- **수명**: 컴퓨터가 켜져 있고 루프가 살아 있는 동안 계속. 잠자기/종료 시 자연히 멈추고, 재개 시 `ROADMAP.md`의 다음 미체크 작업부터 이어감.
- **상태 소스**: 진행 상태는 `ROADMAP.md`의 체크박스 + git 히스토리. 별도 상태파일 없음(재개가 단순).

## 2. 한 반복(iteration)의 절차

1. `ROADMAP.md`에서 **가장 위의 `[ ]` 하위작업**을 고른다.
2. 필요한 만큼 코드를 작성/수정한다 (작업 단위는 1커밋 크기 지향).
3. **검증 게이트**(아래 3절)를 모두 통과시킨다. 실패하면 고친다 — 빨간 상태로 진행 금지.
4. **커밋**: Conventional Commits 형식. (4절)
5. **푸시**: `origin/main`에 직접 푸시.
6. 해당 하위작업을 `[x]`로 바꾸고 짧은 커밋 해시를 적는다(같은/다음 커밋에 포함).
7. 한 줄 진행 로그를 남기고 다음 깨어남을 예약한다.

## 3. 검증 게이트 (푸시 전 필수, 순서대로)

```
npm run typecheck   # tsc --noEmit
npm run lint        # eslint
npm run test        # jest
# UI/번들에 영향 있는 변경이면 추가로:
npx expo export     # 번들 무결성 스모크
```

- 하나라도 실패 → 그 반복은 **수정에 집중**, 통과할 때까지 커밋/푸시하지 않음.
- 테스트가 없는 신규 로직은 가능한 한 최소 테스트를 함께 추가.
- 게이트를 우회/완화하지 않는다(예: 테스트 skip, lint 비활성화로 통과시키기 금지).

## 4. 커밋 / 푸시 정책

- **형식**: `feat: …`, `fix: …`, `chore: …`, `docs: …`, `test: …`, `refactor: …`
- 본문 마지막에 트레일러:
  ```
  Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>
  ```
- **브랜치**: `main` 직접 (사용자 선택). 기능 브랜치/PR 미사용.
- **금지**: force-push, 히스토리 rewrite(`rebase -i`, `reset --hard` 후 push), 대용량 바이너리 무단 커밋.
- 한 커밋 = 한 논리 단위. 통과한 커밋마다 즉시 푸시.

## 5. 안전 수칙

- **비밀키 금지**: API 키/토큰을 코드·데이터·커밋에 절대 넣지 않는다. 런타임은 `expo-secure-store`만 사용. `.env*`, `*.key`는 `.gitignore`.
- `example/`(레퍼런스 이미지)·`docs/`는 임의로 삭제하지 않는다.
- 사용자가 만든/추가한 파일을 설명과 다르게 덮어쓰지 않는다 — 발견 시 멈추고 보고.
- 파괴적/되돌리기 어려운 작업(원격 강제 변경, 대량 삭제)은 진행 전 보고.

## 6. 깨어남 간격 (페이싱)

- 작업 단위가 끝나면 바로 다음 단위로(짧은 간격). 빌드/익스포트 등 외부 대기는 그 소요에 맞춰 폴링.
- 할 일이 없거나(로드맵 소진) 막히면 긴 간격(20~30분)으로 대기하며 사용자 입력을 기다린다.

## 7. 정지 / 에스컬레이션 조건 (멈추고 사용자에게 보고)

- 같은 게이트 실패가 **연속 2~3회** 자력 해결 안 됨.
- 설계 모호성으로 임의 결정이 위험할 때(`DESIGN.md`로 답이 안 나오는 새 결정).
- 외부 의존성 필요(유료 키, 권한, 사용자 기기에서만 가능한 확인).
- 로드맵 소진 → 백로그 정리안을 제시하고 승인 대기.

## 8. 재개 방법

- 새 세션에서: `ROADMAP.md`의 첫 `[ ]`부터 이어서 이 매뉴얼대로 진행.
- 중단 지점이 모호하면 `git log`와 미커밋 변경을 확인해 정합성을 맞춘 뒤 진행.

## 9. 시작 트리거

- 사용자가 **"하네스 시작"**(또는 동등 지시)을 보내면 M0부터 위 절차로 자율 진행을 개시한다.
- 시작 전까지는 설계 문서(`docs/`) 정비만 수행하고 코드 스캐폴딩/커밋은 하지 않는다.
